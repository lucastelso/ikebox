# Ikebox 1.0.0: a primeira versão estável

*Read in English: [v1.0.0.md](https://github.com/lucastelso/ikebox/blob/v1.0.0/docs/releases/v1.0.0.md)*

O **Ikebox** é um cliente de VPN IPsec isolado para Linux, para IKEv1
legado e para IKEv2: *IKE* numa *caixa* (*box*), o motor do
[strongSwan](https://www.strongswan.org/) rodando numa caixa isolada e sem
root. Até a 0.9 ele se chamava **IPsec Client**; é o mesmo app, agora
estável, assinado e aberto.

## Instalar

| Distribuição | Arquivo |
|---|---|
| Fedora, openSUSE, RHEL/Rocky/AlmaLinux 10 | `ikebox-1.0.0-1.x86_64.rpm` |
| Ubuntu, Debian, Linux Mint, Pop!_OS | `ikebox_1.0.0_amd64.deb` |
| Outras | `ikebox_1.0.0_amd64.AppImage` |

- Fedora: `sudo dnf install ./ikebox-1.0.0-1.x86_64.rpm`
- openSUSE: `sudo zypper install ./ikebox-1.0.0-1.x86_64.rpm` (depois de
  importar a chave abaixo)
- Ubuntu/Debian: `sudo apt install ./ikebox_1.0.0_amd64.deb`

O `.rpm` e o `.deb` instalam o componente de rede sozinhos: nada de senha de
administrador no app. O manual completo está em
[docs/pt-BR/instalacao.md](https://github.com/lucastelso/ikebox/blob/v1.0.0/docs/pt-BR/instalacao.md).

## Vindo do IPsec Client

Instale o Ikebox do mesmo jeito, por cima. O `.rpm`/`.deb` substitui o
pacote `ipsec-client`, o componente de rede antigo é removido e, na primeira
execução, o Ikebox move seus perfis, ajustes e credenciais guardadas para os
nomes dele. Com o AppImage, apague o `ipsec-client.AppImage` antigo.

## Conferir o download

Todo arquivo é assinado e atestado pelo build que o gerou.

```bash
curl -fsSLO https://raw.githubusercontent.com/lucastelso/ikebox/v1.0.0/packaging/keys/ikebox-release.asc
gpg --import ikebox-release.asc     # impressão digital: 6F3F 99EA 25FA F76F CF98  655C B357 4751 2185 8FC5
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify <arquivo> --repo lucastelso/ikebox
```

## O que há de novo desde a 0.9.0

- **Nome e logo novos**, e o strongSwan reconhecido no app e no README como
  o motor que faz o trabalho do IPsec.
- **Versões assinadas e geradas na CI**: o `.rpm` e o `SHA256SUMS` são
  assinados com a chave do projeto, e o GitHub atesta qual commit gerou cada
  arquivo.
- **O charon roda sem root**: só com a permissão de rede, com um usuário de
  sistema próprio; o DNS da VPN é aplicado pela parte root do engine, só na
  interface da VPN.
- **Smartcards e tokens USB** (PKCS#11): a chave nunca sai do cartão, e o
  PIN nunca é guardado.
- **Certificados ECDSA e grupos ECP** (o engine agora usa o OpenSSL).
- **Pacotes que cuidam de tudo**: o componente de rede é instalado,
  atualizado e removido junto com o pacote; a linha de comando
  (`ikebox-cli`), com página de manual e autocompletar, vem no `.rpm`/`.deb`.
- **Fechar a janela mantém o Ikebox na bandeja**, e um monitor de estado só
  alimenta a bandeja e a janela.
- **Aviso opcional de atualização** (desligado por padrão): uma vez por dia
  ele olha a última versão e mostra um link; nada é baixado.
- As credenciais só são lembradas depois de uma conexão bem-sucedida.
- Todos os textos de licença dentro dos pacotes, e o código-fonte
  correspondente do engine anexado à versão.

A lista completa está no [CHANGELOG](https://github.com/lucastelso/ikebox/blob/v1.0.0/CHANGELOG.md).

## Limites conhecidos

- O strongSwan anunciou o fim do IKEv1. O Ikebox fica na última versão do
  strongSwan que o tem e recebe as correções de segurança do upstream
  ([ADR-0026](https://github.com/lucastelso/ikebox/blob/v1.0.0/docs/adr/0026-strongswan-maintenance-policy.md)).
- O importador do FortiClient segue o formato documentado do FortiClient;
  ainda não passou por muitas exportações reais.
- Uma conexão por vez; ainda sem verificação de revogação (CRL/OCSP).

## Distribuições testadas

Ubuntu 22.04 e 24.04, Debian 12 e 13, Fedora 45, openSUSE Tumbleweed e
AlmaLinux 10 (com EPEL). RHEL 9 e derivados não têm suporte.
