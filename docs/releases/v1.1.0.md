# Ikebox 1.1.0: for FortiGate users moving to IPsec, and builds without Docker

*Leia em português: [v1.1.0.pt-BR.md](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/releases/v1.1.0.pt-BR.md)*

**Ikebox** is a sandboxed IPsec VPN client for Linux, for legacy IKEv1 and
for IKEv2: *IKE* in a *box*, [strongSwan](https://www.strongswan.org/)'s
engine running in an isolated sandbox without root.

FortiOS 7.6.3 removed SSL-VPN tunnel mode on every FortiGate model, so many
organizations are moving their users to IPsec dial-up, where FortiClient for
Linux offers no IPsec without EMS (and IKEv2 only). That is the case Ikebox
was built for, and this release says so up front.

## Install

| Distribution | File |
|---|---|
| Fedora, openSUSE, RHEL/Rocky/AlmaLinux 10 | `ikebox-1.1.0-1.x86_64.rpm` |
| Ubuntu, Debian, Linux Mint, Pop!_OS | `ikebox_1.1.0_amd64.deb` |
| Others | `ikebox_1.1.0_amd64.AppImage` |

- Fedora: `sudo dnf install ./ikebox-1.1.0-1.x86_64.rpm`
- openSUSE: `sudo zypper install ./ikebox-1.1.0-1.x86_64.rpm` (after
  importing the key below)
- Ubuntu/Debian: `sudo apt install ./ikebox_1.1.0_amd64.deb`

Updating from 1.0.0: install over it; profiles, settings and stored
credentials stay. The full guide is in
[docs/installation.md](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/installation.md).

## Check the download

Every file is signed and attested by the build that made it.

```bash
curl -fsSLO https://raw.githubusercontent.com/lucastelso/ikebox/v1.1.0/packaging/keys/ikebox-release.asc
gpg --import ikebox-release.asc     # fingerprint: 6F3F 99EA 25FA F76F CF98  655C B357 4751 2185 8FC5
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify <file> --repo lucastelso/ikebox
```

## What is new since 1.0.0

- **FortiToken and other one-time codes, said plainly.** Type your password
  followed by the code (`password123456`), which is Fortinet's own method
  for IKEv1. With "The password is a one-time code" on in the profile, it is
  asked at every connection and never stored, not on disk and not in the
  keyring. The credentials dialog and the profile editor now say so. A code
  sent by email or SMS in a second step is not supported yet: if your
  gateway does that, please open an issue with the anonymized log.
- **The engine builds without Docker.** `native-engine/build.sh --host`
  compiles it with your distribution's musl toolchain, offline if you want,
  from sources checked by SHA-256 and GPG. It stays one static executable
  with the same hardening; the official packages still come from the pinned
  builder, byte for byte as before. For packagers (AUR, Nix, COPR, OBS):
  [docs/packaging.md](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/packaging.md).
- **The command line without the desktop app**, for servers, WSL and
  minimal setups: no Node, WebKitGTK or Docker needed to build it.
- **Servers and SSH sessions.** By default only the user at the computer's
  own screen may connect. An optional polkit rule, never installed by the
  packages, lets an administrator allow a group from any session; when
  polkit refuses, the message now says so and where to look
  ([docs/cli.md](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/cli.md#servers-and-remote-sessions)).
- Two Rust advisories in libraries that reach only the app's webview
  (`cookie`, `url`) are fixed; Ikebox was not affected in practice.
- Smaller fixes: `npm ci` works in an unpacked source tarball; the README
  lists what building needs apart from what contributing needs.

The complete list is in the [CHANGELOG](https://github.com/lucastelso/ikebox/blob/v1.1.0/CHANGELOG.md).

## Known limits

- A code sent in a second XAuth step (FortiGate's email or SMS code) is not
  supported yet.
- strongSwan has announced the end of IKEv1. Ikebox stays on the last
  strongSwan release that has it and takes upstream's security fixes
  ([ADR-0026](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/adr/0026-strongswan-maintenance-policy.md)).
- One connection at a time; no revocation checks (CRL/OCSP) yet.

## Tested distributions

Ubuntu 22.04 and 24.04, Debian 12 and 13, Fedora 45, openSUSE Tumbleweed and
AlmaLinux 10 (with EPEL). RHEL 9 and its rebuilds are not supported. The
engine's host build is tested on Fedora 45, Ubuntu 24.04 and Arch.
