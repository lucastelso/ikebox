# IPsec Client 0.9.0 (pre-alpha): import from other VPN clients

*Leia em português: [v0.9.0.pt-BR.md](https://github.com/lucastelso/ipsec-client/blob/v0.9.0/docs/releases/v0.9.0.pt-BR.md)*

Coming from another VPN client? The app now reads its configuration and
turns it into a profile, without reading the passwords in it.

## How to update

1. Install the new package over the old one:
   - Fedora: `sudo dnf install ./ipsec-client-0.9.0-1.x86_64.rpm`
   - openSUSE: `sudo zypper install --allow-unsigned-rpm ./ipsec-client-0.9.0-1.x86_64.rpm`
   - Ubuntu/Debian: `sudo apt install ./ipsec-client_0.9.0_amd64.deb`
   - AppImage: replace the old file with the new one.
2. Open the app. It offers to update the network component (**Update now**):
   nothing in it changed since 0.7.0, but it carries the version number. It
   takes a few seconds and asks for the administrator password.

## What changed

- In **Profiles → Import** (or by dragging the file into the window), the
  app also reads:
  - **Cisco VPN Client** profiles (`.pcf`);
  - **vpnc** configurations;
  - **NetworkManager** connections (vpnc, strongswan and libreswan), with
    their DNS and routes;
  - the old **`ipsec.conf`** of strongSwan and libreswan;
  - **FortiClient** configuration backups (XML).
- The format is recognized by itself. The preview says which one it is and
  what to review.
- **The passwords in these files are never read**, not even the "encrypted"
  group password of a `.pcf`: you type them when connecting.
- Certificates and VPNs that are not IPsec (OpenVPN, WireGuard, L2TP...)
  are refused, saying why and where to go instead.
- From the terminal: `ipsec-client-cli profiles import-legacy <file>`.

## Known limits

- The FortiClient importer follows FortiClient's documented XML format; it
  was not tested with real exports yet. If yours does not import, open an
  issue with the error (never send the file itself: it may hold secrets).
- For Cisco `.pcf` and vpnc, the networks reached through the VPN come from
  the gateway after connecting: the profile asks for everything
  (`0.0.0.0/0`). Set the networks in the editor if only some should go
  through the VPN.

## Tested distributions

Ubuntu 22.04 and 24.04, Debian 12 and 13, Fedora 45, openSUSE Tumbleweed and
AlmaLinux 10 (with EPEL). RHEL 9 and its rebuilds are not supported.

| Your distribution | File |
|---|---|
| Fedora, openSUSE, RHEL/Rocky/AlmaLinux 10 (with EPEL) | `ipsec-client-0.9.0-1.x86_64.rpm` |
| Ubuntu 22.04+, Debian 12+, Mint | `ipsec-client_0.9.0_amd64.deb` |
| Others | `ipsec-client_0.9.0_amd64.AppImage` |

To check the download, in the folder with the files:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```

## Other known limitations

- **Pre-alpha:** validated on a real FortiGate VPN (IKEv1 aggressive + PSK +
  XAuth); the other modes are validated against test gateways only.
- Certificates must be RSA or Ed25519; revocation is not checked.
- **x86_64** only.
- On GNOME, the tray icon needs the AppIndicator extension.
- Closing the window closes the app, but **does not disconnect** the VPN.
