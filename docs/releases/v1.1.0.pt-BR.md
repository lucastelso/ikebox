# Ikebox 1.1.0: para quem sai do SSL-VPN do FortiGate para IPsec, e builds sem Docker

*Read in English: [v1.1.0.md](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/releases/v1.1.0.md)*

O **Ikebox** é um cliente de VPN IPsec isolado para Linux, para IKEv1
legado e para IKEv2: *IKE* numa *caixa* (*box*), o motor do
[strongSwan](https://www.strongswan.org/) rodando numa caixa isolada e sem
root.

O FortiOS 7.6.3 removeu o modo túnel do SSL-VPN em todos os modelos de
FortiGate, e muitas organizações estão migrando seus usuários para IPsec
dial-up, onde o FortiClient para Linux não tem IPsec sem o EMS (e só fala
IKEv2). É o caso para o qual o Ikebox foi feito, e esta versão diz isso logo
de início.

## Instalar

| Distribuição | Arquivo |
|---|---|
| Fedora, openSUSE, RHEL/Rocky/AlmaLinux 10 | `ikebox-1.1.0-1.x86_64.rpm` |
| Ubuntu, Debian, Linux Mint, Pop!_OS | `ikebox_1.1.0_amd64.deb` |
| Outras | `ikebox_1.1.0_amd64.AppImage` |

- Fedora: `sudo dnf install ./ikebox-1.1.0-1.x86_64.rpm`
- openSUSE: `sudo zypper install ./ikebox-1.1.0-1.x86_64.rpm` (depois de
  importar a chave abaixo)
- Ubuntu/Debian: `sudo apt install ./ikebox_1.1.0_amd64.deb`

Atualizando da 1.0.0: instale por cima; os perfis, as configurações e as
credenciais guardadas continuam. O manual completo está em
[docs/pt-BR/instalacao.md](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/pt-BR/instalacao.md).

## Conferir o download

Todo arquivo é assinado e atestado pelo build que o gerou.

```bash
curl -fsSLO https://raw.githubusercontent.com/lucastelso/ikebox/v1.1.0/packaging/keys/ikebox-release.asc
gpg --import ikebox-release.asc     # impressão digital: 6F3F 99EA 25FA F76F CF98  655C B357 4751 2185 8FC5
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify <arquivo> --repo lucastelso/ikebox
```

## O que há de novo desde a 1.0.0

- **FortiToken e outros códigos de uso único, explicados.** Digite a senha
  seguida do código (`senha123456`), que é o próprio método da Fortinet para
  o IKEv1. Com "A senha é um código de uso único" ligado no perfil, ela é
  pedida a cada conexão e nunca é guardada: nem em disco, nem no chaveiro. O
  diálogo de credenciais e o editor de perfis agora dizem isso. Um código
  enviado por e-mail ou SMS numa segunda etapa ainda não tem suporte: se o
  seu gateway faz isso, abra uma issue com o log anonimizado.
- **O motor compila sem Docker.** O `native-engine/build.sh --host` o
  compila com o toolchain musl da sua distribuição, sem rede se você quiser,
  a partir de fontes conferidas por SHA-256 e GPG. Ele continua um
  executável estático com o mesmo endurecimento; os pacotes oficiais seguem
  saindo do builder fixado, byte a byte como antes. Para quem empacota (AUR,
  Nix, COPR, OBS):
  [docs/packaging.md](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/packaging.md)
  (em inglês).
- **A linha de comando sem o app de desktop**, para servidores, WSL e
  instalações mínimas: sem Node, WebKitGTK nem Docker para compilar.
- **Servidores e sessões SSH.** Por padrão, só quem está na tela do próprio
  computador pode conectar. Uma regra opcional do polkit, que os pacotes
  nunca instalam, deixa um administrador liberar um grupo em qualquer
  sessão; quando o polkit recusa, a mensagem agora diz isso e onde olhar
  ([docs/cli.md](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/cli.md#servers-and-remote-sessions),
  em inglês).
- Dois alertas de segurança em bibliotecas Rust que só chegam ao webview do
  app (`cookie`, `url`) foram corrigidos; o Ikebox não era afetado na
  prática.
- Correções menores: o `npm ci` funciona num tarball de código-fonte
  descompactado; o README separa o que é preciso para compilar do que é
  preciso para contribuir.

A lista completa está no [CHANGELOG](https://github.com/lucastelso/ikebox/blob/v1.1.0/CHANGELOG.md) (em inglês).

## Limites conhecidos

- Um código enviado numa segunda etapa do XAuth (o código por e-mail ou SMS
  do FortiGate) ainda não tem suporte.
- O strongSwan anunciou o fim do IKEv1. O Ikebox fica na última versão do
  strongSwan que o tem e recebe as correções de segurança do projeto
  ([ADR-0026](https://github.com/lucastelso/ikebox/blob/v1.1.0/docs/adr/0026-strongswan-maintenance-policy.md)).
- Uma conexão por vez; ainda sem checagem de revogação (CRL/OCSP).

## Distribuições testadas

Ubuntu 22.04 e 24.04, Debian 12 e 13, Fedora 45, openSUSE Tumbleweed e
AlmaLinux 10 (com EPEL). RHEL 9 e derivados não têm suporte. O build do
motor no host é testado no Fedora 45, no Ubuntu 24.04 e no Arch.
