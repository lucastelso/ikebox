# IPsec Client 0.7.0 (pre-alpha): IKEv2 with username and password

*Leia em português: [v0.7.0.pt-BR.md](https://github.com/lucastelso/ipsec-client/blob/v0.7.0/docs/releases/v0.7.0.pt-BR.md)*

The app now connects to gateways that use IKEv2 with a username and password
(EAP-MSCHAPv2), what Windows, macOS and Android call "IKEv2 with a
username". The gateway always proves who it is with its certificate.

## How to update

1. Install the new package over the old one:
   - Fedora: `sudo dnf install ./ipsec-client-0.7.0-1.x86_64.rpm`
   - openSUSE: `sudo zypper install --allow-unsigned-rpm ./ipsec-client-0.7.0-1.x86_64.rpm`
   - Ubuntu/Debian: `sudo apt install ./ipsec-client_0.7.0_amd64.deb`
   - AppImage: replace the old file with the new one.
2. Open the app and click **Update now** on the network component: this time
   it changes (its strongSwan gains what EAP needs), and EAP profiles do not
   connect without it. It takes a few seconds and asks for the administrator
   password.

Coming from 0.2.0 or older, read the notes of
[0.3.0](https://github.com/lucastelso/ipsec-client/blob/v0.7.0/docs/releases/v0.3.0.md)
too: it brought important security fixes.

## What changed

- **IKEv2 with username and password.** In **Profiles → New**, choose
  **IKEv2 with username and password**, fill in the gateway, the name in
  its certificate and its **CA** (choose the `.pem`/`.crt` file or paste the
  text). The editor shows the CA's name and how long it is valid. When
  connecting, the app asks for your username and password, like for XAuth.
- **The gateway is always checked:** its certificate must come from the CA
  in the profile and carry the gateway's name. There is no "accept any
  certificate". Without that check, someone in the path could pose as the
  gateway and collect your password.
- **Clear failures:** a wrong password, a certificate from another CA and a
  wrong gateway name each say what to check.
- **Copy anonymized** also hides the names in certificates (they carry the
  organization's name).

## Known limits

- The gateway certificate must be **RSA or Ed25519**. ECDSA certificates
  (for example from Let's Encrypt with recent certbot) are not supported yet:
  the editor says so when the CA is added.
- **Revocation is not checked** (CRL/OCSP): a revoked gateway certificate
  keeps working until it expires. Details in
  [SECURITY.md](https://github.com/lucastelso/ipsec-client/blob/v0.7.0/SECURITY.md).

## Tested distributions

Ubuntu 22.04 and 24.04, Debian 12 and 13, Fedora 45, openSUSE Tumbleweed and
AlmaLinux 10 (with EPEL). RHEL 9 and its rebuilds are not supported.

| Your distribution | File |
|---|---|
| Fedora, openSUSE, RHEL/Rocky/AlmaLinux 10 (with EPEL) | `ipsec-client-0.7.0-1.x86_64.rpm` |
| Ubuntu 22.04+, Debian 12+, Mint | `ipsec-client_0.7.0_amd64.deb` |
| Others | `ipsec-client_0.7.0_amd64.AppImage` |

To check the download, in the folder with the files:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```

## Other known limitations

- **Pre-alpha:** validated on a real FortiGate VPN (IKEv1 aggressive + PSK +
  XAuth); the other modes, EAP included, are validated against test
  gateways only.
- No client certificates yet: they come in the next phase (ADR-0024).
- **x86_64** only.
- On GNOME, the tray icon needs the AppIndicator extension.
- Closing the window closes the app, but **does not disconnect** the VPN.
