# IPsec Client 0.3.0 (pre-alpha): audit fixes, more distributions, lighter

*Leia em português: [v0.3.0.pt-BR.md](https://github.com/lucastelso/ipsec-client/blob/v0.3.0/docs/releases/v0.3.0.pt-BR.md)*

This version brings the fixes of a three-part audit of 0.2.0 (credentials,
privilege boundaries, compatibility), works on more distributions, and is
lighter. Everyone using 0.2.0 should update, **including the network
component**.

## How to update (important)

1. Install the new package over the old one:
   - Fedora: `sudo dnf install ./ipsec-client-0.3.0-1.x86_64.rpm`
   - openSUSE: `sudo zypper install --allow-unsigned-rpm ./ipsec-client-0.3.0-1.x86_64.rpm`
   - Ubuntu/Debian: `sudo apt install ./ipsec-client_0.3.0_amd64.deb`
   - AppImage: replace the old file with the new one.
2. Open the app. In **System → Network component**, click **Update** and type
   the administrator password.
3. Connect as usual.

Most fixes live in the network component: without step 2, it is still the
0.2.0 one.

## What was fixed

Security and privacy (full report: [audit of 0.2.0](https://github.com/lucastelso/ipsec-client/blob/v0.3.0/docs/audits/v0.2.0.md)):

- **Your VPN username no longer shows up in logs**, including in "Copy
  anonymized", when the credentials were not remembered.
- **A crash no longer writes credentials to disk** (no core dumps).
- On a computer with more than one user:
  - another user can no longer read the end of your VPN log;
  - a user of the active session can no longer make the network component
    delete another program's network interface.
- Text sent by the VPN gateway can no longer drive your terminal through the
  command line log.
- The network component is harder to misuse: it runs with no privileges
  beyond what it needs, a slow program can no longer hold it, and the
  embedded strongSwan no longer opens files named by the user's side.
- Installing the network component from the `.rpm`/`.deb` no longer runs a
  file that a program running as you could swap.

Compatibility:

- The `.deb` and `.rpm` now bring everything the app needs (`pkexec`, `ip`
  and others were missing on minimal installations).
- **Works on Fedora Silverblue/Kinoite and other image-based systems** (the
  network component failed to install there; tested in a simulation).
- **System → Diagnostics** now tells when systemd-resolved is not running
  (the default on Debian and openSUSE), which leaves the VPN's internal names
  unresolved.
- When the VPN's remote network contains the gateway's own address, the
  tunnel no longer swallows its own traffic.

## Lighter

- The embedded strongSwan is one self-contained executable that does not
  depend on your system's libraries; the network component is half the size.
- The app no longer carries the Docker engine meant for development: it is
  18% smaller.

## Tested distributions

The packages and the VPN engine are tested automatically on Ubuntu 22.04 and
24.04, Debian 12 and 13, Fedora 45, openSUSE Tumbleweed and AlmaLinux 10
(with EPEL). RHEL 9 and its rebuilds are not supported.

| Your distribution | File |
|---|---|
| Fedora, openSUSE, RHEL/Rocky/AlmaLinux 10 (with EPEL) | `ipsec-client-0.3.0-1.x86_64.rpm` |
| Ubuntu 22.04+, Debian 12+, Mint | `ipsec-client_0.3.0_amd64.deb` |
| Others | `ipsec-client_0.3.0_amd64.AppImage` |

On Debian and openSUSE, install `systemd-resolved` to resolve the VPN's
internal names (see the installation guide). Prefer the `.rpm` or the `.deb`:
the AppImage carries its own libraries, which do not get your distribution's
security updates.

To check the download, in the folder with the files:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```

## Known limitations

- **Pre-alpha:** validated on a real FortiGate VPN (IKEv1 aggressive + PSK +
  XAuth), but still with few users.
- **x86_64** only.
- A gateway named by mDNS (`.local`) is not resolved; use its DNS name or
  address.
- On GNOME, the tray icon needs the AppIndicator extension.
- Closing the window closes the app, but **does not disconnect** the VPN. Use
  **Disconnect**.
- Before removing the package, remove the network component in **System →
  Network component → Remove**.
