# IPsec Client 0.5.0 (pre-alpha): IPsec modes and security level

*Leia em português: [v0.5.0.pt-BR.md](https://github.com/lucastelso/ipsec-client/blob/v0.5.0/docs/releases/v0.5.0.pt-BR.md)*

Every IPsec mode a profile can describe is now tested end to end, each
profile says how safe its settings are, and failures in IKEv2 are explained.

## How to update

1. Install the new package over the old one:
   - Fedora: `sudo dnf install ./ipsec-client-0.5.0-1.x86_64.rpm`
   - openSUSE: `sudo zypper install --allow-unsigned-rpm ./ipsec-client-0.5.0-1.x86_64.rpm`
   - Ubuntu/Debian: `sudo apt install ./ipsec-client_0.5.0_amd64.deb`
   - AppImage: replace the old file with the new one.
2. Open the app and click **Update now** on the network component: this time
   it carries a fix (below). It takes a few seconds and asks for the
   administrator password.

Coming from 0.2.0 or older, read the notes of
[0.3.0](https://github.com/lucastelso/ipsec-client/blob/v0.5.0/docs/releases/v0.3.0.md)
too: it brought important security fixes.

## What changed

- **Security level per profile.** A badge says **good**, **legacy** or
  **weak**: on the profile card, when importing, and under the state on the
  connection screen. Open the profile in **Profiles** to read why (for
  example: aggressive mode with a PSK, small Diffie-Hellman groups, SHA-1, a
  group PSK with XAuth). **It is only a warning:** the VPN still connects;
  only whoever runs the gateway can change these settings.
- **Every mode the profile accepts is tested** on the same path as the app
  (helper and embedded strongSwan 6.1.0): IKEv1 main or aggressive mode,
  PSK with or without XAuth, IKEv2 with PSK; with and without NAT-T, PFS,
  virtual IP, split and full tunnel. The table is in
  [profiles.md](https://github.com/lucastelso/ipsec-client/blob/v0.5.0/docs/profiles.md#supported-modes).
- **Clearer failures:** in IKEv2, "the gateway requires the client to ask for
  a virtual IP" is now its own message, and a wrong PSK in IKEv1 main mode no
  longer looks like an unreachable gateway.
- The credentials dialog of a profile without XAuth asks for the
  "pre-shared key" instead of a "group PSK".

## Fixed

- **Profiles without a virtual IP** (`"request_vip": false`) connected but
  sent no traffic through the tunnel: the route was never installed. The fix
  is in the network component, so update it.

## Tested distributions

Ubuntu 22.04 and 24.04, Debian 12 and 13, Fedora 45, openSUSE Tumbleweed and
AlmaLinux 10 (with EPEL). RHEL 9 and its rebuilds are not supported.

| Your distribution | File |
|---|---|
| Fedora, openSUSE, RHEL/Rocky/AlmaLinux 10 (with EPEL) | `ipsec-client-0.5.0-1.x86_64.rpm` |
| Ubuntu 22.04+, Debian 12+, Mint | `ipsec-client_0.5.0_amd64.deb` |
| Others | `ipsec-client_0.5.0_amd64.AppImage` |

To check the download, in the folder with the files:

```bash
sha256sum -c SHA256SUMS --ignore-missing
```

## Known limitations

- **Pre-alpha:** validated on a real FortiGate VPN (IKEv1 aggressive + PSK +
  XAuth); the other modes are validated against test gateways only.
- No EAP or certificates yet: they are designed (ADR-0022 to ADR-0024) for
  the next phases.
- **x86_64** only.
- On GNOME, the tray icon needs the AppIndicator extension.
- Closing the window closes the app, but **does not disconnect** the VPN.
