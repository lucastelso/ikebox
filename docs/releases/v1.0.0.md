# Ikebox 1.0.0: the first stable release

*Leia em português: [v1.0.0.pt-BR.md](https://github.com/lucastelso/ikebox/blob/v1.0.0/docs/releases/v1.0.0.pt-BR.md)*

**Ikebox** is a sandboxed IPsec VPN client for Linux, for legacy IKEv1 and
for IKEv2: *IKE* in a *box*, [strongSwan](https://www.strongswan.org/)'s
engine running in an isolated sandbox without root. Up to 0.9 it was called
**IPsec Client**; this is the same app, now stable, signed and open.

## Install

| Distribution | File |
|---|---|
| Fedora, openSUSE, RHEL/Rocky/AlmaLinux 10 | `ikebox-1.0.0-1.x86_64.rpm` |
| Ubuntu, Debian, Linux Mint, Pop!_OS | `ikebox_1.0.0_amd64.deb` |
| Others | `ikebox_1.0.0_amd64.AppImage` |

- Fedora: `sudo dnf install ./ikebox-1.0.0-1.x86_64.rpm`
- openSUSE: `sudo zypper install ./ikebox-1.0.0-1.x86_64.rpm` (after
  importing the key below)
- Ubuntu/Debian: `sudo apt install ./ikebox_1.0.0_amd64.deb`

The `.rpm` and the `.deb` install the network component themselves: no
administrator password in the app. The full guide is in
[docs/installation.md](https://github.com/lucastelso/ikebox/blob/v1.0.0/docs/installation.md).

## Coming from IPsec Client

Install Ikebox the same way, over it. The `.rpm`/`.deb` replace the
`ipsec-client` package, the old network component is removed, and on its
first start Ikebox moves your profiles, settings and stored credentials to
its own names. With the AppImage, delete the old `ipsec-client.AppImage`.

## Check the download

Every file is signed and attested by the build that made it.

```bash
curl -fsSLO https://raw.githubusercontent.com/lucastelso/ikebox/v1.0.0/packaging/keys/ikebox-release.asc
gpg --import ikebox-release.asc     # fingerprint: <FINGERPRINT>
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify <file> --repo lucastelso/ikebox
```

## What is new since 0.9.0

- **A new name and logo**, and strongSwan credited in the app and the
  README as the engine that does the IPsec work.
- **Signed releases built in CI**: the `.rpm` and `SHA256SUMS` are signed
  with the project key, and GitHub attests which commit built each file.
- **charon runs without root**: only with the network capability, as its own
  system user; the VPN DNS is set by the engine's root part, on the VPN
  interface only.
- **Smartcards and USB tokens** (PKCS#11): the key never leaves the card,
  and the PIN is never stored.
- **ECDSA certificates and ECP groups** (the engine now uses OpenSSL).
- **Packages that manage everything**: the network component is installed,
  updated and removed with the package; the command line (`ikebox-cli`),
  with a manual page and completions, comes in the `.rpm`/`.deb`.
- **Closing the window keeps Ikebox in the tray**, and one status monitor
  feeds the tray and the window.
- **An optional update notice** (off by default): once a day it looks at the
  latest release and shows a link; nothing is downloaded.
- Credentials are remembered only after a successful connection.
- Every license text inside the packages, and the engine's corresponding
  source attached to the release.

The complete list is in the [CHANGELOG](https://github.com/lucastelso/ikebox/blob/v1.0.0/CHANGELOG.md).

## Known limits

- strongSwan has announced the end of IKEv1. Ikebox stays on the last
  strongSwan release that has it and takes upstream's security fixes
  ([ADR-0026](https://github.com/lucastelso/ikebox/blob/v1.0.0/docs/adr/0026-strongswan-maintenance-policy.md)).
- The FortiClient importer follows FortiClient's documented format; it has
  not met many real exports yet.
- One connection at a time; no revocation checks (CRL/OCSP) yet.

## Tested distributions

Ubuntu 22.04 and 24.04, Debian 12 and 13, Fedora 45, openSUSE Tumbleweed and
AlmaLinux 10 (with EPEL). RHEL 9 and its rebuilds are not supported.
